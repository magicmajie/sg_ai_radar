# Singapore AI Radar 公开活动指南 · 生图规范

> 本文档写给负责生成每期图片的 AI 助手（ChatGPT）。数据字段的定义以 [DATA_SPEC.md](DATA_SPEC.md) 为准，本文只规定图片怎么做。
> 版本：v1.0（2026-11-26）。以仓库 main 分支上的最新版本为准。

## 1. 设计定位

- 栏目名称：**Singapore AI Radar｜新加坡 AI 活动指南**
- 读者：新加坡华人 AI 开发者、创业者和技术实践者
- 风格：克制、简洁、现代科技感，**信息优先**
- 只做客观分类：**不显示**推荐等级（A/B/C）、个人相关度评分或任何个人化判断。这些内容只出现在个人报告里，见 [PERSONAL_REPORT_SPEC.md](PERSONAL_REPORT_SPEC.md)
- 两个并列类别，视觉权重相同：
  - **技术与开发**（TECH & BUILDERS），对应 `category: tech`
  - **创业与社群**（FOUNDERS & COMMUNITY），对应 `category: community`

## 2. 画布与视觉系统

### 2.1 画布

| 项目 | 规定 |
|---|---|
| 比例 / 尺寸 | 竖版 3:4，**1080 × 1440 px** |
| 格式 | PNG，sRGB |
| 拼图 | 不允许。每页一张独立文件 |
| 安全边距 | 48–60 px，文字和关键信息不得进入边距 |
| 间距单位 | 8 px 的倍数 |
| 卡片圆角 | 20–24 px |

### 2.2 字体

| 用途 | 字体 |
|---|---|
| 中文 | Noto Sans SC（思源黑体） |
| 英文、数字 | Inter，或 Noto Sans |

字号（以 1080 × 1440 画布为基准）：

| 元素 | 字号 |
|---|---|
| 封面主标题 | 88–104 px |
| 页面标题 | 52–64 px |
| 活动详情卡标题 | 56–72 px |
| 列表中的活动名称 | 31–36 px |
| 正文 | 28–32 px |
| 信息标签 | 24–28 px |
| 页脚 | 22–24 px |

**最小字号 22 px。** 内容放不下时增加页数，不缩小字号。

### 2.3 配色

| 用途 | 色值 |
|---|---|
| 深色封面背景 | `#101A35` |
| 深色标题区 | `#171E3B` |
| 主文字 | `#17213A` |
| 次级文字 | `#536079` |
| 通用浅色背景 | `#F4F6FC` |
| 信息卡片 | `#FFFFFF` |
| 分隔线 | `#DDE3EF` |
| 技术类主色 | `#5148C8` |
| 技术类浅色背景 | `#EEEDFC` |
| 创业类主色 | `#167D92` |
| 创业类浅色背景 | `#E9F5F7` |
| “待核实”文字 | `#697386` |

类别颜色只按 `category` 使用：技术类的徽章、标签、图标用技术类主色，创业类用创业类主色，两种颜色不混用。

### 2.4 图标与装饰

- 统一使用简洁线条图标，推荐 [Lucide](https://lucide.dev)，线宽保持一致。
- 图标**必须配中文字段名**，不能只放图标。
- 渐变、光线、抽象科技图形只做装饰，不能压在文字上、不能降低可读性。

## 3. 每期图片组成

标准一期 9 张：5 张固定页 + 4 张精选详情卡。

| 序号 | 文件名 | 页面 |
|---|---|---|
| 01 | `01-cover.png` | 封面 |
| 02 | `02-overview.png` | 本期概览 |
| 03 | `03-list-tech.png` | 技术与开发活动一览 |
| 04 | `04-list-community.png` | 创业与社群活动一览 |
| 05–08 | `05-featured-<活动id>.png` … | 精选活动详情卡，顺序与 `issue.md` 的 `featured` 一致 |
| 09 | `09-focus.png` | 本期重点关注 |

**数量变化时的规则**：
- 某类活动一页放不下：在该类列表页后面紧跟续页，如 `04-list-tech-2.png`，后面的序号顺延。
- 精选少于 4 场：减少详情卡，序号顺延。
- 某类本期没有活动：省略该类列表页，概览页显示“0 场”。
- 序号连续、不跳号，`issue.md` 的 `images` 与文件夹内文件完全一一对应。
- 页面类型顺序固定：封面 → 概览 → 技术列表（含续页）→ 创业列表（含续页）→ 精选卡 → 重点关注。

所有页面右上角或页脚统一显示 `Singapore AI Radar`。

## 4. 各页面规范

### 4.1 封面 `cover`

| 元素 | 内容来源 |
|---|---|
| 栏目名 | 固定：`Singapore AI Radar`、`新加坡 AI 活动指南`、`Singapore AI Events Guide` |
| 日期范围 | `issue.md` 的 `period_start`–`period_end`，如“未来 14 天活动｜11月26日 – 12月9日” |
| 活动总数 | `issue.md` 的 `events` 数量（**程序计算**） |
| 3–4 条内容概括 | 根据本期活动撰写，每条 ≤ 14 字 |

背景用深色封面背景 `#101A35`，可以搭配滨海湾夜景、城市天际线或简洁城市轮廓。

### 4.2 本期概览 `overview`

- 活动总数，以及两个类别各自的场数（**程序计算**）
- 每个类别 3–5 条主题概括，每条 ≤ 14 字，只概括本期实际有的活动
- 两个类别左右或上下并列，大小、视觉权重相同

### 4.3 活动一览 `list-tech` / `list-community`

页面标题：“技术与开发活动一览（N 场）”/“创业与社群活动一览（N 场）”，N 由程序计算。

每场活动一行，包含：

| 元素 | 来源 |
|---|---|
| 日期 + 星期 | `start`，如 `12.08（二）`，**星期由程序计算** |
| 开始时间 | `start`，如 `18:30` |
| 官方英文名称 | `display_title`，没有则用 `title` |
| 组织方 | 写成“组织方：XXX”，来源 `organizer.name`；列入 `unverified` 时写“组织方：XXX（待核实）” |
| 1–2 个短标签 | `labels` |
| 报名状态提示 | 仅当 `status` 不是 `open` 时显示：候补 / 已满 / 已截止 / 延期 / 状态待核实 |

- 按 `start` 从早到晚排序。
- **每页 6–8 场**。超过 8 场就加续页，不缩小字号，不删减活动。
- `status: cancelled` 的活动不出现在图片里。

### 4.4 精选活动详情卡 `featured-<活动id>`

顶部：类别徽章（技术与开发 / 创业与社群）、标题（`display_title` 或 `title`）、副标题（`subtitle`，有才显示）。

信息区，每行“图标 + 中文字段名 + 内容”：

| 字段名 | Lucide 图标 | 内容来源 | 示例 |
|---|---|---|---|
| 组织方 | `building-2` | `organizer.name` | Menlo Research |
| 日期 | `calendar-days` | `start`，星期由程序计算 | 12月8日（星期二） |
| 时间 | `clock` | `start`–`end`；有 `doors_open` 时加注 | 18:30 – 20:30（18:00 入场） |
| 地点 | `map-pin` | `venue.name`，第二行 `venue.address` 简写；`venue.tba: true` 时写“报名通过后公布” | National Library, Level 7 |
| 费用 | `banknote` | `price.type` + `price.note` | 免费 / SGD 25 / 待核实 |
| 报名 | `ticket` | `registration.note`；`status` 非 `open` 时显示状态 | 需注册并通过审核 |

- 费用统一用**纸币线条图标**（`banknote`），文字写完整：“免费”“免费（饮品自费）”“SGD 25”“待核实”。
- 任何列入 `unverified` 的字段，内容写“待核实”，用 `#697386` 颜色。

正文区三个栏目：

| 栏目 | 来源 |
|---|---|
| 目标参与人群 | `card.audience` |
| 主要交流主题 | `card.theme` |
| 活动形式与亮点 | `card.highlights` |

### 4.5 本期重点关注 `focus`

三个区块：
1. **值得关注的技术方向**：3–6 个短词
2. **活跃的社区与组织**：3–6 个，来自本期活动的 `organizer.name`
3. **报名及参与小贴士**：3–4 条，每条 ≤ 20 字

内容必须基于本期活动。不把少数几场活动的主题夸大成整个行业的趋势。

## 5. 分类与精选

**分类**（详见 DATA_SPEC 2.4）：
- 技术与开发：以技术分享、工程实践、开源贡献、项目演示、联合开发、Hackathon 为主
- 创业与社群：以创业交流、产品商业化、社区社交、业务合作、创业生态为主
- 两种属性都有的活动，按主要议程归入一类，**不重复出现**

**精选**：
- 通常 4 场，写在 `issue.md` 的 `featured` 里
- 优先：信息完整（尽量没有待核实字段）、有明确交流环节、有实际项目展示或主题有代表性
- 兼顾两个类别
- 精选不代表其他活动质量较低，图片上不做“推荐/不推荐”之类的表述

**短标签**：来自 `labels`，每场 1–2 个，每个 ≤ 8 个字符。

## 6. 素材禁区

- 不用虚构的参会者、人脸特写、虚构的现场照片
- 不用与活动无关的具象机器人形象
- 不虚构或仿制主办方 Logo
- 不用过度浓烈的霓虹灯、商业广告式视觉
- 不把主办方原始海报放进图片或存进仓库
- 优先用抽象科技图形、几何结构、代码符号和适度留白

---

## 7. 准确性：推荐的生成方式

生图模型容易写错中文、错位日期、漏掉活动。因此采用**混合生成**：

1. **AI 生图只负责背景和装饰**：生成不含任何文字的背景图（如封面的城市夜景、抽象几何装饰）。
2. **程序负责所有事实性文字**：用代码（如 Python + Pillow，或 HTML 渲染截图）把活动数据排版到背景上。日期、星期、时间、组织方、地点、费用、报名状态、活动数量、日期范围全部从数据文件读取或计算，**不手打、不让生图模型写**。
3. 最终图片仍由 ChatGPT 生成并提交。

背景图可以复用：同一类页面（如所有列表页）每期用同一张背景，不必每期重新生成。可复用的无文字背景图存放在 `assets/backgrounds/`，命名如 `cover-bg.png`、`list-bg.png`。换新背景时用新文件名，如 `cover-bg-v2.png`，不要覆盖旧文件。

## 8. 工程侧（Claude）检查项

ChatGPT 提交后，工程侧会检查以下内容，不通过的会列出具体问题：

**自动检查**（每次提交后运行）：
- [ ] 每张图 1080 × 1440，PNG
- [ ] 文件名格式、序号连续，与 `issue.md` 的 `images` 一一对应
- [ ] 页面类型顺序符合第 3 节
- [ ] 精选卡数量和顺序与 `featured` 一致，对应的活动文件存在且填写了 `card.*`

**人工 / 视觉检查**（Claude 逐张查看）：
- [ ] 列表页包含本期该类别的全部活动，没有遗漏、没有重复、没有已取消的活动
- [ ] 日期、星期、时间、组织方、地点、费用、报名状态与活动文件一致
- [ ] `unverified` 字段显示为“待核实”
- [ ] 活动数量、日期范围正确
- [ ] 没有文字溢出、截断、重叠或乱码
- [ ] 没有违反第 6 节素材禁区
